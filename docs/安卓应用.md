# 安卓应用

`android/` 是一个把移动线生成搬到手机上的应用：WebView 套壳同一份
`web-generator` 页面，推理与模拟都在本机离线完成，不需要服务器。

## 结构

| 目录 | 内容 |
| --- | --- |
| `app/src/main/java/com/mcscai/generator/` | Kotlin：应用外壳、WebView 桥、任务队列、草稿与历史、导出 |
| `app/src/main/assets/` | `oooi-scmls-v1-preview.pt`、`oooi-scmls-v1.1-preview.pt`（PyTorch Lite 格式）与模型元数据 |
| `app/src/main/jniLibs/arm64-v8a/` | 由 `buildNative` 任务生成的 `libmcscai_native.so` |
| `native/` | Rust：JNI 桥、任务与摆放、视角变换、判定器移植、引擎绑定 |
| `tools/` | 权重导出与校验脚本 |

## 构建

需要 Android SDK（compileSdk 34）、NDK 26.1.10909125、Rust 与 `cargo-ndk`。

```bash
# 1. 页面产物：应用内置的是 web-generator 的构建结果
cd web-generator && npm ci && npm run build
mkdir -p ../android/app/src/main/assets/www
rsync -a --delete dist/ ../android/app/src/main/assets/www/

# 2. 工具链
cargo install cargo-ndk --version 3.5.4
sdkmanager "ndk;26.1.10909125"

# 3. 构建 APK（buildNative 任务会自动交叉编译原生库）
cd ../android
export ANDROID_HOME=/path/to/android-sdk
export ANDROID_NDK_HOME=$ANDROID_HOME/ndk/26.1.10909125
./gradlew assembleDebug
```

产物在 `android/app/build/outputs/apk/debug/app-debug.apk`，只发布 arm64-v8a。
原生库与权重都不在仓库里：前者由 `buildNative` 现场编译，后者需要用下面的脚本
从训练检查点导出。

## 导出 PyTorch Lite 权重

安卓只能读 **Lite 格式**，跟服务端用的普通 TorchScript 归档不是一回事：

| 格式 | 写出方式 | 关键成员 | 谁能读 |
| --- | --- | --- | --- |
| 服务端 | `scripted.save()` | `data.pkl`、`code/` | Python 的 `torch.jit.load` |
| 移动端 Lite | `scripted._save_for_lite_interpreter()` | `bytecode.pkl`、`constants.pkl` | 安卓的 Lite 解释器 |

用错格式的症状是 `PytorchStreamReader failed locating file bytecode.pkl`，看着像文件坏了，
其实两边都正常。两条命令：

```bash
python android/tools/export_model.py        # 导出 oooi-scmls-v1-preview
python android/tools/export_test2_model.py  # 导出 oooi-scmls-v1.1-preview

# 校验落盘后的文件真是 Lite 格式，并跑一遍推理
python android/tools/lite_check.py \
  --model android/app/src/main/assets/oooi-scmls-v1.1-preview.pt \
  --checkpoint data/generation/oooi-scmls-v1.1-preview/run/final.pt
```

导出脚本里有两处必须注意的细节：`freeze` 默认只保留 `forward`，
`generate` 要靠 `preserved_attrs` 显式保留；补丁源码必须落成磁盘上的真实文件再导入，
因为 TorchScript 用 `inspect.getsource` 从 `__file__` 重新读源码。

## 运行时约束

* 加载权重必须用 `org.pytorch.LiteModuleLoader`，不能用 `org.pytorch.Module.load`。
  Lite 包只带 `libpytorch_jni_lite.so`，后者指向的 `libpytorch_jni.so` 在 AAR 里不存在，
  症状是 `dlopen failed: library "libpytorch_jni.so" not found`。两者签名一致，
  编译期不会报错。
* 页面不能用 `file://` 加载。Vite 产物是 `<script type="module">`，模块脚本按 CORS 规则
  抓取，`file://` 下安卓 WebView 会拒绝执行——HTML 和 CSS 都正常，JS 一行不跑，界面全白
  且没有可见报错。应用用 `WebViewAssetLoader` 把 assets 挂到
  `https://appassets.androidplatform.net/assets/` 下，同时让 `localStorage` 与 `IndexedDB`
  真正可用。
* 三维画布优先用 WebGPU，探测不到适配器时退回 WebGL，两条分支都必须显式打开阴影
  （`renderer.shadowMap.enabled = true`）。
* 三个渲染器后端固定使用 Three.js 0.181.2：0.179.1 在目标数字贴图释放后会让缓存绑定
  持有 `null`，再次标点或切换结构预览时崩溃。

## 模型清单

应用内置两个版本，启动时读取草稿里的 `model_id` 恢复上次选择，
权重加载期间仍可切换，未就绪的模型显示「加载中」。
