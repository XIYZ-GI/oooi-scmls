# 部署指南

从一台干净的 Linux 服务器开始，到网页能用为止。下面所有命令都在仓库根目录执行。

## 一、环境要求

| 项目 | 要求 |
| --- | --- |
| 系统 | 任意能跑 Docker 的 Linux（Debian 12 / Ubuntu 22.04 及以上实测可用） |
| Docker | 20.10 以上，带 `docker compose` v2 子命令 |
| 内存 | 4 GiB 起；生成服务加载权重后常驻约 1 GiB |
| 磁盘 | 10 GiB 起（镜像约 2.5 GiB，其余留给数据） |
| CPU | 4 核起。生成是 CPU 推理，核越多单任务越快 |

首次构建要联网拉取基础镜像与 PyPI、npm 依赖；之后可以完全离线运行。

## 二、首次部署

```bash
git clone <本仓库地址> oooi-scmls
cd oooi-scmls

# 可选：自定义端口
cp .env.example .env
vi .env

# 构建三个镜像（会编译 Rust 引擎和前端页面，视机器约 5～15 分钟）
sudo docker compose build

# 启动
sudo docker compose up -d

# 看状态，等 backend 变成 healthy
sudo docker compose ps
```

`.env` 可配置项：

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `MCSCAI_FRONTEND_PORT` | `15175` | 网页工作台对外端口 |
| `MCSCAI_BACKEND_PORT` | `8010` | 后端接口对外端口，接口文档在 `/api/docs` |
| `MCSCAI_LOG_LEVEL` | `info` | 后端日志级别 |

## 三、访问地址

把下面的 `SERVER_IP` 换成服务器外网 IP：

| 用途 | 地址 |
| --- | --- |
| 模拟工作台 | `http://SERVER_IP:15175/` |
| 移动线打标器 | `http://SERVER_IP:15175/#labeler` |
| 搜索与训练 | `http://SERVER_IP:15175/#search` |
| AI 移动线生成 | `http://SERVER_IP:15175/#generate` |
| 后端接口 | `http://SERVER_IP:8010` |
| 接口文档 | `http://SERVER_IP:8010/api/docs` |

云服务器需要放行这两个端口的安全组规则。只想暴露一个端口时见下面「用 Nginx 反代」。

### 自检

```bash
# 后端健康检查
curl -s http://127.0.0.1:8010/api/health

# 生成服务模型清单：两个模型的 ready 都应为 true
curl -s http://127.0.0.1:15175/api/generation/models
```

网页里也可以直接验：打开 `#generate`，选一个模型，填 7×5×2、两个目标点、
8 个候选，点生成，能在几十秒内出候选并回放就说明整条链路通了。

## 四、三个服务各是什么

| 服务 | 容器内端口 | 职责 |
| --- | --- | --- |
| `backend` | 8000 | 模拟会话与 WebSocket、结构库、打标样本与自动时序、搜索任务 |
| `generation` | 8001 | 移动线模型加载、候选生成、判定与回放落盘 |
| `frontend` | 80 | 托管静态页面，并把 `/api/`、`/api/generation/`、`/ws/` 反代到上面两个服务 |

前端容器用 Nginx 的 Docker 内置 DNS（`127.0.0.11`）动态解析后端地址，
后端容器重启换 IP 后会重新解析，不会一直连旧地址。

## 五、数据放在哪、怎么备份

`data/` 通过只读挂载之外的方式直接挂进两个容器，重启或重建容器都不会丢：

| 文件 / 目录 | 内容 |
| --- | --- |
| `data/mcscai.sqlite3` | 结构库、打标样本、自动时序、生成草稿与任务 |
| `data/search.sqlite3` | 搜索任务与候选 |
| `data/generation/web/` | 生成任务记录、逐任务回放（`replay-*.json.gz`）与导出缓存 |
| `data/label-replays/` | 打标回放 |

数据库跑在 WAL 模式，**不要只复制主文件**，要用 SQLite 的备份接口：

```bash
sudo docker compose exec -T backend python - <<'PY'
import sqlite3
for name in ("mcscai", "search"):
    source = sqlite3.connect(f"/app/data/{name}.sqlite3")
    target = sqlite3.connect(f"/app/data/{name}-backup.sqlite3")
    with target:
        source.backup(target)
    source.close(); target.close()
    print(name, "备份完成")
PY
```

模型不在 `data/` 里，而是在 `models/`（只读挂载）。

## 六、日常运维

```bash
# 看日志
sudo docker compose logs -f backend
sudo docker compose logs -f generation

# 只重启（没有改代码、没有改依赖时用这个，几秒完成）
sudo docker compose restart

# 改了 Python / Rust / 前端源码后重新构建
sudo docker compose build
sudo docker compose up -d

# 停止（保留数据）
sudo docker compose down

# 停止并删除数据卷（会丢结构库与打标样本，慎用）
sudo docker compose down
sudo rm -rf data/
```

### 只换模型权重

```bash
# 1. 把新权重写进 models/，并按 models/README.md 的格式登记到 models.json
python -m scripts.training.deploy \
  --checkpoint data/generation/<实验目录>/run/final.pt \
  --model-id <版本编号> --name <显示名> --status "<成绩说明>"

# 2. 生成服务重新读取注册表（权重是只读挂载，不需要重建镜像）
sudo docker compose restart generation
```

如果注册表里的 `checkpoint_sha256` 与磁盘上的文件对不上，生成任务会直接报
「模型文件摘要与已注册版本不一致」，这是刻意的：宁可报错，也不要用到错版本的权重。

### 用 Nginx 反代到域名 + HTTPS

把 15175 只开给本机，在外层再放一个 Nginx：

```nginx
server {
    listen 443 ssl http2;
    server_name your.domain;
    ssl_certificate     /etc/letsencrypt/live/your.domain/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/your.domain/privkey.pem;

    location / {
        proxy_pass http://127.0.0.1:15175;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;   # WebSocket 模拟会话需要
        proxy_set_header Connection "upgrade";
        proxy_set_header Host $host;
        proxy_read_timeout 300s;
    }
}
```

只对外暴露 443，`MCSCAI_FRONTEND_PORT` 与 `MCSCAI_BACKEND_PORT` 都收到本机即可。

## 七、不用 Docker 的部署

适合二次开发。需要 Rust 1.88、Python 3.11、Node 20 以上。

```bash
# 1. Rust 引擎扩展 + 前端静态页面
python3 -m venv .build && . .build/bin/activate
pip install maturin==1.9.1
cargo install cargo-watch --version 8.5.2   # 可选，开发用
./scripts/build_local_artifacts.sh

# 2. 后端
python3 -m venv .venv && . .venv/bin/activate
pip install -r server/requirements.txt server/wheels/*.whl
MCSCAI_DATA_DIR=data uvicorn app.main:app --app-dir server --host 0.0.0.0 --port 8010

# 3. 生成服务（另开一个终端）
python3 -m venv .venv-generation && . .venv-generation/bin/activate
pip install -r training/requirements.txt
MCSCAI_DATA_DIR=data MCSCAI_MODELS_DIR=models \
  uvicorn training.web.app:app --host 0.0.0.0 --port 8001

# 4. 前端静态产物交给任意静态服务器；开发时直接跑 Vite
npm --prefix frontend install
npm --prefix frontend run dev        # 默认代理到 127.0.0.1:8010
```

`frontend/nginx.conf` 是给容器用的配置（服务名固定为 `backend` / `generation`）；
本机运行时要么改这两个 upstream 地址，要么直接用 `npm run dev`。

## 八、故障排查

| 现象 | 原因与处理 |
| --- | --- |
| 网页一直显示「正在建立模拟会话」 | `backend` 还没健康。`docker compose ps` 看状态，`docker compose logs backend` 看报错 |
| 界面提示「模拟服务连接失败」 | 前端连不到后端。确认 8010 端口、防火墙与 `frontend` 容器的反代配置 |
| `curl /api/generation/models` 返回模型 `ready: false` | `models/` 没挂进容器，或 `models.json` 里 `path` 指向的文件不存在 |
| 生成任务报「模型文件摘要与已注册版本不一致」 | 权重被改动或注册表没更新，重跑 `scripts/training/deploy.py` |
| 生成很慢 | 逐格自回归解码本来就慢。降低网格体积与候选数量；生成容器不要和训练抢 CPU |
| 数据库写不进去 | `data/` 目录权限不对。`sudo chown -R 1000:1000 data/` 或按需放宽 |
| 前端 502 | 后端容器 IP 变了但 Nginx 缓存了旧地址。容器内 DNS 缓存 10 秒，稍等即恢复；持续 502 就 `sudo docker compose restart frontend` |

## 九、资源占用参考

| 服务 | 空闲内存 | 说明 |
| --- | --- | --- |
| `backend` | 约 80 MiB | 一个 Uvicorn 进程，搜索任务另外起低优先级子进程 |
| `generation` | 约 1 GiB | PyTorch CPU 常驻，加载权重后基本不再增长 |
| `frontend` | 约 10 MiB | 纯 Nginx 静态托管 |

镜像体积：`backend` 约 350 MiB，`generation` 约 1.4 GiB（大部分是 PyTorch CPU），
`frontend` 约 70 MiB。
