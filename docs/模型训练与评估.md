# 模型训练与评估

这一页讲两个发布模型是怎么练出来的、怎么复现，以及怎么把权重发到网页上。
数据从哪来见 [数据合成器](../data-synthesizers/README.md)。

## 一、两个模型的关系

两个模型的网络宽度、头数、层数、步数、学习率、预热与随机种子**完全相同**，
唯一的结构差异是相对位置编码：

| | `oooi-scmls-v1-preview` | `oooi-scmls-v1.1-preview` |
| --- | --- | --- |
| 参数量 | 10,808,901 | 10,887,548 |
| 相对位置 | 编码器 `clamp(-8, 8)` 等距档；解码器九档「距离分档＋符号表」 | 三轴每个有符号整数格距独立查表，不合档也不截断 |
| 训练数据 | 158,842 条 | 170,226 条（旧 158,842 + 新生成器 11,384） |
| 综合航械题 | 273 / 400 | 307 / 400 |

三套历史题上两者统计上没有差别（99 对 100、90 对 91、79 对 77），差距全部来自新生成器
那 100 道（39 对 5）。也就是说这次提升主要来自数据覆盖面，而不是相对位置编码本身；
把编码换回旧的、数据保持不变，成绩会退回去。

## 二、需求特征

两个版本都读**十二维**需求：

* 几何九项：网格宽、高、厚度，目标横纵坐标及各自的极值等；
* 目标三项：目标数量、时序分组数与负载列数。

**不读**目标 z、每轮刻数、连续轮数与每目标负载数。这四项只决定验收标准，
所以网页上对应的输入框会被隐藏，草稿里即使残留历史值也会被归一化成固定协议
（连续三轮、每目标十块负载、每轮不设刻数上限）。

## 三、准备训练数据

先用 `data-synthesizers/` 里的四份代码合成记录（每份都会写出 `records.sqlite3`），
再冻结成训练集：

```bash
python -m scripts.training.dataset \
  --name oooi-scmls-v1.1-preview \
  --output data/generation/oooi-scmls-v1.1-preview \
  --source <合成器1>/records.sqlite3 \
  --source <合成器2>/dataset.jsonl.gz \
  --source <合成器3>/records.sqlite3 \
  --source <合成器4>/records.sqlite3
```

产出两个文件：

* `dataset.jsonl`：每行一条 `{id, task, proposal}`；
* `manifest.json`：记录来源、条数、逐文件 SHA-256 与整体数据指纹。

`oooi-scmls-v1-preview` 用同一批数据中较早的 158,842 条，做法一样，只是 `--source`
少一份、`--output` 换成 `data/generation/oooi-scmls-v1-preview`。

## 四、训练

必须在 GPU 上跑（CPU 只用于推理与评估）：

```bash
pip install -r training/requirements.txt

# oooi-scmls-v1-preview：相对位置偏置
python -m scripts.training.relpos

# oooi-scmls-v1.1-preview：精确相对位置编码
python -m scripts.training.test2
```

两个入口都会：

1. 读 `dataset.jsonl`，按网格体积排序后建编码缓存；
2. 按体积分档抽样组批，注意力规模与有效格数双重限流；
3. 用 bf16 前向反向、梯度裁剪 1.0、AdamW（权重衰减 0.01）；
4. 每 50 步写 `run/metrics.jsonl`，每 500 步存 `run/last.pt`，结束存 `run/final.pt`。

断点里写了数据指纹与网络配置，**换了数据或改了网络就不能续训**，会直接断言失败——
这是为了避免把两个不同实验的进度接在一起。中断后重跑同一条命令即可接着训，
续训段用小学习率余弦衰减。

训练参数集中在 `scripts/training/config.py`，改步数、学习率和网络宽度都只改那里。

## 五、评估

四套百题放在 `benchmarks/`，各 100 道：

| 内部键 | 展示名 |
| --- | --- |
| `historical188` | 基础航械题 |
| `historical200` | 简单航械题 |
| `previous300` | 普通航械题 |
| `today100` | 普通航械题-2 |

```bash
# 四套全跑（GPU 生成 + 多进程 CPU 判定）
python -m scripts.training.evaluate \
  --checkpoint data/generation/oooi-scmls-v1.1-preview/run/final.pt \
  --model-id oooi-scmls-v1.1-preview \
  --benchmarks benchmarks --workers 32 --device cuda

# 只要一套
python -m scripts.training.evaluate \
  --checkpoint ... --model-id ... --suite today100 --workers 16 --device cpu
```

评估口径与网页推理页完全一致：

* 每道题生成 **8 个确定性候选**（横截面交换 × 翻转的八种等距变换，贪心解码、不采样）；
* 负载按该候选结构本列最前方块 +2 摆放；
* 判定「连续三轮、每列目标推过十块负载」，不额外要求每个活塞都激活过。

结果写在 `<实验目录>/evaluation/<版本编号>/`：逐题一个 JSON、每套一份 `report.json`，
四套跑完再合成 `combined.json`（也就是「综合航械题 400 道」）。逐题结果是可续跑的：
中断后重跑会跳过已完成的题目，因此长评估可以分几次做完。

## 六、发布权重到网页

```bash
python -m scripts.training.deploy \
  --checkpoint data/generation/oooi-scmls-v1.1-preview/run/final.pt \
  --model-id oooi-scmls-v1.1-preview \
  --name oooi-scmls-v1.1-preview \
  --status "综合航械题 307/400" \
  --default
```

命令会把检查点精简成推理权重（去掉优化器状态，体积从 131 MB 降到 43 MB），
写进 `models/<版本编号>.pt` 并更新 `models/models.json`，
然后 `sudo docker compose restart generation` 让生成服务重新读取注册表。

## 七、单条需求做推理

不想起服务时，可以直接用命令行跑一条需求：

```bash
python -m training.inference \
  --checkpoint models/oooi-scmls-v1.1-preview.pt \
  --task task.json --output result.json --candidates 8 --seed 41
```

`task.json` 就是网页里的需求草稿：

```json
{"width": 7, "height": 5, "depth": 2, "max_ticks": 0,
 "targets": [{"x": 1, "y": 2, "z": 0, "order": 1}],
 "rounds": 3, "load_blocks": 10}
```

输出里带每个候选的结构、推动点与判定结果，`status` 为 `success` 表示至少有一个
候选完整通过。
